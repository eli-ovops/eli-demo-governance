## 1. 用户收到什么

每个项目交付一个能冷启动、能保存、能导出、能恢复的本机工具，以及预置的虚构示例。最终由协调 PMO 汇总为一个交付入口，列出三个工具的启动方式、结果包、验收记录和已知问题。三个工具各自运行、各自保存，任何一个失败不影响另外两个。

首版价值分别是：客户需求到范围与报价的版本衔接；已有脚本到逐平台文字准备包；项目结论到原始证据的定位与缺口检查。保存和导出是基础，不能用三个空表单或静态看板作为完成结果。规则和模板如实标识，首版无模型调用、无平台登录、无发布动作。

## 4. 保存 版本 导出与恢复

显式保存是首版主路径。每份编辑有 dirty 状态、已提交 revision 和保存确认；服务端串行写入并核对前置 revision。旧标签页冲突提示“内容已有更新，你的编辑仍保留”，提供复制或浏览器下载当前文本。第二进程对同一数据根不能成为第二写入者；更换端口不解除这项约束。残留锁须核对所属进程及数据根，不能直接删锁或强制覆盖。

JSON 存储用同目录临时文件、完整校验、持久化和替换；SQLite 使用事务与受支持备份方式。正常启动遇到缺库、损坏、未来 schema、失去挂载或根身份不匹配时停止相关写入，不能自动初始化空数据。根身份用于识别误选目录，不以机器名绑定、也不因换机器就禁止合法隔离恢复。工具只保证已确认提交的恢复；未保存文本可在仍打开的页面下载，不承诺浏览器或设备崩溃后的零丢失。外置盘仍可作为工程目录，实际数据根须明确登记，丢盘时不假装能读取同盘备份。

冻结、变更采纳和导出锁定明确的已提交 revision 与依赖；旧范围/脚本/许可改变后旧版本继续保留，但不继续作为当前有效版本。FDE 非重复逻辑动作的重试用 requestKey + 请求摘要约束，同 key 不同内容拒绝，不采用最后写入胜出。

导出分内部恢复资料与可对外阅读文字。对外文字从独立字段白名单构造，先预览、明确许可；缺许可/源变化/依赖过期时仅保留内部草稿或剔除受影响字段，不能用“草稿”标签绕过敏感信息保护。内部数据包不含凭据、会话秘密和其他客户资料。

每次导出新建 exportId，在临时包中完成所有文件、校验摘要和清单，最后标 COMPLETED；失败标 FAILED/PARTIAL，不对用户显示成功，不覆盖旧包，不擅自删除失败现场。对外包提交完成及每次新下载前只核当前许可/核准依赖是否仍有效；已撤销或失效则拒绝受影响的公开包/下载，不重读正文改变锁定内容，也不继续使用旧许可。用户此前取得的文件不会被工具追回或删除。预算上限覆盖数据、历史、备份、导出和在途文件，分别说明；超限保留旧数据和撤销许可/下载未保存文本通道，不自动清理，也不任意允许超限增长。

恢复仅导入工具自身支持的备份到新数据根，校验后启动独立副本；不做日常库覆盖、冲突字段合并或真实数据切换。导入的读取/公开许可、正式流程 PASS 和核准记录均是历史资料，不能重新生效。FDE 的两库备份必须有应用级写入屏障、在途写入排空、同批次清单、引用核对；先用合成库演练，不读写真实旧库。JSON 资料导出不能冒充 SQLite 完整备份。

## 5. 验收与冷启动

每份 PRD 将 P0 合并为 3—5 个业务组，给出约 5 个端到端验收场景。每条标明 Given/When/Then、夹具名、操作/命令、期望输出、回执位置和负责 Owner。状态含时间判断时用可注入 now()，只用于测试内部，不暴露改系统时间的业务接口。合成夹具随源码交付；磁盘/权限/损坏故障仅在隔离夹具或文件系统适配器注入，不拔真实盘、不改真实资料权限。

必要验证：真实浏览器主链（桌面与窄窗口）、保存/冲突/重启、一次支持的导出与隔离恢复、相应安全边界、FDE 受影响旧流程回归。390px 是窄浏览器窗口验证，不宣称手机能连接 loopback。可以复用现有浏览器工具，不强制 Playwright 可用作为唯一门槛。测试覆盖指场景覆盖，不要求无依据的 80%/100% 代码行覆盖，也不增加假想风险审查。

无障碍首版覆盖表单标签、键盘操作、可见焦点、文字错误、窄窗口可读；不冒称通过完整 WCAG 认证。安全至少保护敏感 GET/写入/下载，loopback + 会话/启动认证、Host/Origin、工具静态根、纯文本显示与路径约束。具体会话方法由 Owner 依现有基础选择，秘密不写入 URL 查询、日志、PRD、导出。不把同一 OS 用户的恶意软件、完整磁盘损坏、未经批准网络数据根列为已防护能力。

最终包须有测试过的双击启动文件或等效一次启动入口、runtime 绝对位置/版本、工作目录、数据根、端口/URL、启动停止和恢复说明、预置虚构样例、实际导出样例、场景回执、已知问题。端口占用提示并可在工具自己的登记内择空闲端口，不杀其他进程。无需用户自己完成 build 才算交付。

新会话冷启动：读取本 PRD、共同规范、项目当前状态和最后实施回执；核版本/路径/未完成项/累计额度/原 Owner，差异定向补读；接续未完成阶段，不重新起项目或重跑已有有效验收。实施中维护本工具自己的 STATUS、运行/恢复说明和已知问题；其他项目台账保持各自唯一权威。schema 升级只在新任务和相应授权中做隔离副本验证。

## 6. 三工具关系与共同清单

统一文字和导出契约，不建设共享服务、SDK、数据库、登录平台或自动同步。所有交叉引用固定 producer/object/revision/hash/业务维度；引用不会复制成另一份可编辑业务真值。

共同 manifest 最小字段：`producerApp`、`appVersion`、`schemaName`、`schemaVersion`、`exportId`、`createdAt`、`sourceRevisionRefs`、`files[{relativePath,sha256,bytes}]`、`verificationCoverage`、`limitations`、`privacyMode`、`status`。时间用带时区 ISO 8601；file path 为包内相对路径，不允许目录穿越。schema 相容性用于核对结果，不承诺三个应用自动互相导入。

文档修订号统一 Rev2，与软件 appVersion 分开；状态写“修订完成，实施未启动”。本机原件证据链接仍用绝对路径，运行路径可配置并记录，不为了可移植性破坏本机可点击来源。
