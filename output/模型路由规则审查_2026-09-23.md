## 发现并修正的缺口

| 原有缺口 | 修正 |
| --- | --- |
| 任务同时符合多个档位，没有决策次序 | 先核任务级指定和授权，再看风险；不可拆开的混合任务按较高需求，普通不确定任务用 Sol Medium。 |
| “可升级”未说明由谁真正操作 | 执行者提交依据，PMO 负责下次已授权续接的参数调整，不能口头自切模型或新建替身任务。 |
| “返回证据”可能只是参数回显 | 区分目标、请求和实际值；本次实际运行无证据时逐字段标 UNKNOWN。 |
| 旧 PMO 不会自动读新文档 | 添加版本标识；下次已授权派单/续接时检查变化并重读，不批量唤醒闲置任务。 |
| 派发成功后可能停止跟进 | 用户要求完成的工作必须在当前轮跟进至完成、受阻或需用户决定，随后审原始验收证据。 |
| 超时、模型错误可能导致重复创建和重复操作 | 先核任务及请求状态，模型支持/限额问题与能力不足分开处理。 |
| “高成本”“收口”“节流”含义不清 | 明确调度分类、约束范围和触发后的行为，保留原有阈值；不冒充官方计费倍率。 |
| “整体闭环”缺少判定标准 | 分别记录规则已读、路由核实、业务验收；缺项不能整体通过，单任务不能代表全部任务。 |

## 情景走查

以下是文档逻辑推演，不是实际任务运行测试。

| 场景 | 规则要求的结果 |
| --- | --- |
| 低风险表格整理、结果易核验 | Luna Low；少量推理可 Medium。 |
| 边界清楚的普通功能开发 | Sol Medium；有复杂度依据可 High。 |
| 短指令要求删除生产数据 | 先查具体授权和风险，不能按字数选 Luna，也不能因选 Astra 获得删除权限。 |
| 用户明确固定 Luna，但发现其不适合任务 | 报告依据与替代建议，不能私自覆盖或带问题验收。 |
| 仅指定 Sol、未指定思考强度 | 补齐适用 effort，不误判为用户指定 High。 |
| 网络超时或权限不足 | 先定位环境/权限原因，不把换强模型当修复，也不重复提交结果不明的业务操作。 |
| 同一 Bug 两次修正仍失败 | 评估是否为能力问题；有新根因可继续修正，必要时 PMO 调整下一次续接参数，不机械升级。 |
| Astra High 仍无法解决 | 重看根因、材料和范围；无依据不重复执行，不自行开 Max/Ultra。 |
| 创建返回排队或 clientThreadId | 查既有任务和真实 ID，不重复创建，不把排队当完成。 |
| 只读任务实际模型无法核实 | 标 UNKNOWN；允许已有授权内低风险工作，但不能宣称路由和整体闭环已验证。 |
| 旧 PMO 恢复工作或任务仍在执行 | 前者检查版本、按需重读；后者不因调模型重复派发/强停，不擅自恢复暂停任务。 |
| 实时 5h 用量 75%，或周用量 75% | 前者不增加高成本执行；后者等待在途执行收口后串行派发。必要验收保留，多条件取严。 |
