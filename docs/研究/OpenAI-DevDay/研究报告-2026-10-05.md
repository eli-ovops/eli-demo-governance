# OpenAI DevDay 2026 首轮研究报告

核查基准：用户本地日期 2026-10-05，Asia/Shanghai。首轮范围约 30 分钟上限，提前收敛；没有运行模型/API 付费验证。本文是公开资料研究与判断，不是产品实现、账户可用性验收或客户交付。

## 1. 结论与届次

截至核查日，最近已经举办且可核实的是 **OpenAI DevDay 2026**，2026-09-29 在旧金山 Fort Mason 举办。开幕主旨演讲安排在 10:00 PDT，换算北京时间为 9 月 30 日 01:00。活动页仍保留会前措辞，但同日官方回顾已发布，因此不能仅凭报名页把活动误判为尚未举行。[官方活动页](https://devday.openai.com/)、[9 月 29 日官方回顾](https://openai.com/index/devday-2026-recap/)。后续 DevDay Exchanges 的计划不计入本届已完成事实；2025 届内容不混入 2026 发布。

对创业型 FDE 最值得借鉴的是：用明确任务、受控工具、可核结果形成企业工作流，再用评测决定模型与成本。平台正在提供执行、协作和分发基础设施，创业者的差异化应落在业务知识、接入、纠错和客户验收，而非重复做一个通用聊天框。这是本报告基于发布材料的判断，不是已验证商业结果。

**Decisions API 名称已获官方证据**，但目前可核状态仍是有限预览。官方描述为：输入文本或图片上下文，对用户指定的问题从预定义有限答案中选择，适合分类、路由或下一步动作选择；底层使用 Luna。它是接口产品，不能直接等同于 `gpt-6-luna` 模型调用，也没有证据表明直接调用 Luna 就获得同样的延迟、协议或成本。[官方回顾的 Decisions API 章节](https://openai.com/index/devday-2026-recap/)。

## 3. 接口、模型、成本与延迟

模型像“能力引擎”；API 是程序向它提交任务的接口；Agents API 还管理执行循环、会话与工具；Codex、Work、dots 是包含界面和权限的产品；Ultrafast 是速度档位。更换模型不能自动获得托管执行，买 ChatGPT 套餐也不自动等于获得 API 余额。

| 项目 | 核实标识/入口 | 已核公开价格 | 延迟证据与缺口 |
| --- | --- | --- | --- |
| Sol | `gpt-6.1-sol`；`POST /v1/responses`，另支持无工具 Chat Completions | Standard 每百万 token：输入 $2、缓存输入 $0.10、缓存写入 $2.50、输出 $10 | 未见通用于用户业务的 p50/p95；“接近 Astra”是官方评测定位，不是 Eli 识别准确率 |
| Luna | `gpt-6-luna`；Responses/Chat Completions，工具用法须看各接口限制 | Standard 每百万 token：输入 $0.10、缓存 $0.01、缓存写入 $0.125、输出 $0.50 | 适合集中、高量任务的官方定位；不提供 Decisions 的独立延迟证据 |
| Astra | `gpt-6-astra`；Responses | Standard 每百万 token：输入 $10、缓存 $1、缓存写入 $12.50、输出 $50 | 更强任务定位，不保证每个任务的总成本更高或更低 |
| Ultrafast | Responses 请求设置 `service_tier: "ultrafast"`，模型为 Astra | 定价页有独立档位；本轮文本抽取没有完整保留 tab 标签映射，故不把未确认档位的数字写成确定价格 | 回顾称 API token 生成最高 6 倍，文档标题称最高 8 倍：来源口径不一致，保留差异。均非完整任务耗时保证 |
| Agents API | `POST /v1/agents/sessions`；SDK `beta.agents.sessions.create`；beta header `OpenAI-Beta: agents=v1` | 框架无额外 API 费用；模型、工具和托管 sandbox 按相应标准费率收费 | 有运行和事件示例，没有本业务的冷启动/任务 p95 数据 |
| Decisions API | 产品名称和 Luna 关系确认；endpoint、schema、SDK、专用 model 标识 UNKNOWN | 独立价目 UNKNOWN；不得套用 Luna token 价当作 Decisions 报价 | 数值延迟、吞吐、SLA UNKNOWN；“real-time”不是毫秒实测 |

价格来源：[官方定价页](https://developers.openai.com/api/docs/pricing)、[Sol 模型页](https://developers.openai.com/api/docs/models/gpt-6.1-sol)、[Luna 模型页](https://developers.openai.com/api/docs/models/gpt-6-luna)。Standard 数字限短上下文，超过 272K 输入时按长上下文档位计价；工具、区域和运行时间另计。接口来源：[Agents quickstart](https://developers.openai.com/api/docs/guides/agents-api/quickstart)、[Ultrafast](https://developers.openai.com/api/docs/guides/ultrafast-mode)。本轮没有执行任何示例。

**体验可行性**：普通模型页有 Playground 入口，Agents 有公开 beta 示例；只能确认文档入口存在，无法确认本人账号已获权限或有余额。Decisions 未找到公开“立即试用”入口，也未找到全面发布的后续官方证据；不推断候补名单存在。

**地域与企业条件**：API 支持国家列表未列中国大陆；如果业务实际从中国大陆提供/访问，官方支持范围就是会改变选型的前提，不能用已有 ChatGPT 登录状态替代。本人实际访问地区与企业运营实体 UNKNOWN。[支持地区](https://developers.openai.com/api/docs/supported-countries)。Ultrafast 仅支持美国驻留及 global processing；Agents API 目前只支持美国驻留、不支持 ZDR，自建 sandbox 也不能改变这一点。[Agents 概览](https://developers.openai.com/api/docs/guides/agents-api/overview)。若客户硬性要求非美国驻留或 ZDR，当前该托管方案不满足，需调整架构而非等同于普通困难。

## 4. 对四类工作有什么借鉴价值

以下为研究推论，尚无客户付费、数据或本地测试证据。

| 场景 | 借鉴点 | 可先复用的现有办法 | 暂时不值得投入 |
| --- | --- | --- | --- |
| 创业型 FDE | 把需求变成一个可验收业务闭环；工具授权、错误恢复与现场接入是交付价值 | 现有 Responses、结构化输出、确定性规则、人工审核；复杂长期任务再考虑托管 agent | 自建通用多 agent 平台；以新名称代替客户问题验证 |
| 企业 SaaS | 插件与事件提供嵌入现有工作入口的机会；独立 SaaS 仍可保留自有流程 | 现有 webhook/任务队列/显式工具函数；插件作为新增入口而非全部产品 | 假定目录上架就有流量；假定所有用户套餐都能抵消推理成本 |
| Eli AI 录单 | 值得学习字段抽取、异常分流、可追溯人工纠错，优先固定单据范围 | 图片理解或 OCR 后文本＋结构化字段＋金额/必填/重复规则；先比较人工录入基线 | 宣称现有 L0 Demo 已具真实识别；直接上 agent 操作 ERP；承诺 100% 准确 |
| 量化研究 | 对新闻、公告和研究证据做主题分类、去重与复核队列，支持离线研究 | 时间冻结材料、规则/关键词基线、有限枚举的结构化输出、独立回放评测 | 毫秒级交易决策、自动下单、从分类成绩推断收益；Ultrafast 不解决数据泄漏和时点问题 |

[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) 已能约束输出字段与枚举，是有限答案分类的现有技术基线。它只约束结构，不保证业务答案正确；拒绝与输出截断等边界仍需处理。Decisions 是否显著改善速度、成本或质量，需要未来接口和相同任务证据，当前不能断言。

## 5. 最多三个值得进一步考虑的方向

本轮不运行验证。三项仅列候选，建议下一轮只选择方向一的“客户审核流程是否值得付费”这一关键未知做最小验证；通过后才进入获授权下一步，其他风险在执行中处理，不并行开展三项研发。以下预算与阈值是本报告建议，不是已经通过的验收。

### 方向一：单一单据类型的审核与异常分流（首选）

先看阻碍：① **关键未知**：用户愿不愿为审核节省时间付费，未见本轮客户证据。② **硬边界**：当前 Eli 是 L0 Mock；没有真实 OCR/LLM、客户样本或 ERP 接入证据，不能据此承诺生产能力。③ **可解决困难**：业务字段、模糊值、金额校验和人工退回规则需要固定，复杂度可通过只做一种单据收敛。

可行性：流程验证可行，真实识别与商业收益待证。最小验证建议：一次 45 分钟、1 名实际审核者的流程访谈，仅用 5 个自编虚构案例和现有 Mock，零付费 API；不自动联系客户。通过：对方指出一个高频痛点、确认审核规则与可接受错误，并愿意明确一个试点价格或预算讨论入口。停止/调整：痛点只需普通导入模板解决，或不愿承担审核且要求零错误自动入账。该验证不证明识别准确率或真实节省工时。

### 方向二：企业事件触发的证据整理与待审核队列

先看阻碍：① **关键未知**：目标企业是否有授权可用的事件/读取接口。② **条件硬阻断**：若必须非美国驻留或 ZDR，当前 Agents API 不满足。③ **可解决困难**：事件重放、去重、身份和审核步骤需要设计；MCP Events 不支持的传输方式必须改用受支持方式。

可行性：先整理证据并供人审核，有明确接口时可行。成熟替代是普通 webhook＋规则＋任务队列，不必为了新发布采用完整 agent。最小验证建议：60 分钟、最多 3 次官方文档读取，选一种事件做“权限—输入—结果—人工审核”纸面追踪，零安装零外写。通过：每个所需字段都有官方读取路径、事件身份和接受条件；停止：唯一输入需要未授权数据，或客户条件与支持范围冲突。可缩减成定时只读报告。

### 方向三：量化研究的公告/新闻分类助手

先看阻碍：① **关键未知**：样本有没有真实发布时间、授权和可靠标签，缺失会使评测无效。② **关键未知**：Decisions 的实际延迟/价目/资格未公开核实，不宜让它成为架构依赖。③ **可解决困难**：错误分类和未来信息泄漏可用冻结样本、未知类及人工复核控制。

可行性：作为离线研究分流可行；不能据此评价交易能力。最小验证建议：在后续独立授权下，用 30 条合法公开、冻结时点的材料，90 分钟内做人工标签与简单规则基线，不调用付费模型。通过：标签可复现、每条能追溯来源和时间，且规则确实留有语义难例；停止：时间不明、标签主观到无法复核，或规则已足够。只有通过后再单独批准模型对照预算；最终衡量误分、拒答、成本和 p95，不把研究分类标签接入交易。
